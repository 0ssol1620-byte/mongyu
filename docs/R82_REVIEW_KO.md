# R82 렉·캐릭터·음향·연출 검토

2026-11-14. 기준: GitHub 0ssol1620-byte/mongyu, codex/r80-mobile-polish HEAD 62c4a1d. 작업 브랜치 codex/r81-motion-audio-performance에서 R82를 구현했다. 로컬 소스/실행본을 수정했으며 원격 push와 스토어 배포는 수행하지 않았다. 이전 Codex Cloud 대화/실행 기록 전체에는 접근하지 않았다.

## 원작 확인

신봉구의 2007-10-04 제작자 글 [Nom 3: An Advanced Mobile Game Created with LOVE](https://www.gamedeveloper.com/game-platforms/-i-nom-3-i-an-advanced-mobile-game-created-with-love)은 작은 사각형이 조합·변형되는 100개 이상의 배경, 매끄러운 움직임과 전위적인 시청각 경험을 설명한다. 글에 실린 플레이 스크린샷 두 장에서 밝은 색면, 사각 타일, 가느다란 인물 실루엣을 확인했다. 조사용 이미지를 게임에 포함하지 않았다.

- 사이키델릭한 연출을 되살려야 한다는 지적에는 근거가 있다. R80의 표시 코드가 기존 사각 타일 렌더러를 우회하고 차분한 곡선/타원으로 바꾼 사실도 확인했다. R82는 사각 타일과 챕터별 색을 중심에 둔 새 아트다.
- 기존 복구 코드에는 stage01~stage10 및 이야기/타이틀/보스 음악 역할과 이전 선택 회피가 있었다. 실제 일반 플레이는 한 곡을 공유했다. 이번에는 10개 전용 곡을 제작했다. 원작의 정확한 곡·악기·챕터 대응표는 원본 음원 대조 없이 확정할 수 없다. 챕터별 고정 음악은 몽유의 재해석이다. 기존 무작위 역할 정책은 컨트롤러 기본값으로 유지하고 앱만 chapterScores:true를 선택한다.
- 제작자 글은 소리의 중요성을 뒷받침하지만 효과음의 전체 샘플·타이밍을 알려 주지는 않는다. 이번 효과음도 새 합성음이다.
- 두 스크린샷과 글만으로 원작 전체의 말풍선 존재·문구·조건을 확정하지 못했다. 현재의 짧은 조작/감탄 표현과 이야기 화면을 원작 대사로 주장하지 않는다.
- 완전 복원 판정은 불가하다. 100개 슬롯/74개 물리 경로와 이번 비교 검사는 원작 실기기 동등성이나 정상 입력 완주를 증명하지 않는다.

## 성능 원인과 수정

프로파일링에서 nativeGeometry가 각 점마다 Assembly.projectSurfacePoint를 부르고 그 함수가 전체 네 면의 지형을 복사·검증하는 비용이 대부분이었다. 표시 어댑터는 엔진이 검증한 스냅샷에서 같은 정수 좌표를 읽고 스냅샷이 바뀔 때만 지형을 만든다. 원래 projector와 표본 좌표·센티널 판단을 대조했다.

이전 map.drawCommands도 다음 프레임의 중간 복사에 계속 포함됐다. 원래 presenter가 새 명령을 만들기 직전에 비우던 출력 목록을 native tick 직전에 먼저 비운다. 캡처 버퍼·난수·충돌 필드는 유지한다. 74개 물리 슬롯 × 12단계를 원래 tick과 비교해 전체 nativeFrame, trace, effects, 입력 이벤트와 결과의 동일성을 확인했다. 짧은 비교이며 장시간/전체 완주 증명은 아니다.

인물은 같은 벽·같은 행동의 연속 이동에서 이전/현재 위치를 보간한다. 최대 한 네이티브 갱신만큼의 표시 지연이 생길 수 있다. 회전·행동 변화·충격·재시작·큰 이동은 즉시 표시한다. 판정 좌표나 저장 데이터는 이동시키지 않는다.

DPR은 최대 1.5, 일반 화면은 약 120만 픽셀로 제한한다. 아주 큰 CSS 화면에서는 최소 DPR 1이 우선한다. 배경 캐시는 12Hz로 그리되 인물의 화면 갱신 주기를 낮추지 않는다.

측정 도구는 tools/verify_browser.cjs다. Chromium, 390×844 CSS px, 기기 DPR 2, CDP CPU 4배 감속, 120개 화면 주기를 사용한다. 실제 RAF/tick 외에 각 주기마다 draw 한 번을 추가하는 스트레스 검사다. Android FPS 보장이 아니다. 비교 수치는 evidence/r82-browser-comparison.json을 따른다. 반복 편차와 네이티브 틱의 순간 비용이 여전히 남는다.

## 캐릭터·오디오

무릎·발을 독립 사인파로 움직이던 방식을 없앴다. 허벅지·종아리는 일정 길이이며 발 목표점에 따라 무릎을 계산한다. 한 주기의 60%는 접지, 나머지는 회수다. 공중 자세와 노인/동행 인물을 구분한다. 자동 검사는 관절 길이를 확인하지만 미술 품질의 최종 판단은 실제 플레이 관찰이 필요하다.

음악은 타이틀 64초, 10개 챕터/보스 각각 약 27~36초의 루프다. 서로 다른 템포·음계·베이스·멜로디·타악 패턴을 사용한다. 외부 샘플이나 놈3 녹음은 없다. 모든 파일을 소스에 포함해 네트워크 준비와 큰 외부 음원 다운로드를 없앴다. 곡 변경에는 크로스페이드, 자체 곡 반복에는 짧은 페이드를 적용한다. 미디어 요소/MP3에서 모든 기기의 샘플 단위 무간극 재생을 보장하지는 않는다.

PCM 효과음은 AudioContext별로 캐시한다. 실제 상태 변화에서 착지/코너 소리를 한 번만 내며 음소거·일시정지·백그라운드 처리는 기존 권한 경로를 따른다. 합성/진폭 검사는 실제 스피커·이어폰의 청음 평가를 대신하지 않는다.

## 검증·수익·출시

- 웹 전체 검사: 112개 중 111개 통과, 실패 0, 외부 감사 어댑터 1개 생략. 이후 색 대비 조정에는 표시 및 배포 HTML 집중 검사를 추가했다.
- 여섯 엔진/판정 파일의 R79 기준 SHA-256은 유지한다. 표시 어댑터와 출력 명령 정리는 별도 모듈이다.
- UTF-8 및 LF/CRLF 입력에서 같은 HTML을 생성하는 검사를 통과했다.
- 브라우저 검사는 타이틀→옷장 저장 복구→이야기→달리기→일시정지/재개→첫 조작 뒤 안내 숨김, 320×568 / 390×844 / 844×390 / 800×1280 화면을 다룬다. 네트워크 차단 상태에서 HTML을 요청 가로채기로 제공해 외부 리소스 없이 부팅되는지도 검사한다. 관리 브라우저 정책이 file:// 탐색을 차단해 해당 방식은 이 환경에서 직접 검증하지 못했다.
- Android에는 R82 HTML/versionCode 82를 준비했다. 현재 Android SDK가 없어 새 APK 컴파일·설치·실기기 렉 검증은 수행하지 않았다.

수익 모델은 [기존 출시 계획](R81_RELEASE_REVIEW_KO.md)의 선택형 꾸미기·확장팩·요청형 보상 광고와 노출 제한을 유지한다. 계정·검증 서버 연결 전에는 플레이에 판매 문구를 끼우거나 로컬 저장으로 유료 권한을 주지 않는다. 실상품 제작, 스토어 계정·구매 검증·복구·환불·광고 검증·개인정보 동의 연결 전까지 수익화 완료가 아니다.

출시 전에는 100개 기억 정상 입력 완주, 저사양 Android 장시간 프레임/발열/청음, 전화·알림 복귀, 거래 전체 경로, 서명 AAB와 심사가 남아 있다. 현재 구현을 1위 보장이나 출시 완료라고 표현하지 않는다.

R82 현재 HTML을 실제 Java의 suspend/back 표현식으로 호출하는 새 VM 계약 검사 5개도 모두 통과했다. 이전 R31 전용 Android 검사 24개는 22개가 실패했다. 고정된 R31 해시/버전 및 오래된 DOM/Canvas 스텁이 원인이며 R81 기준본에서도 똑같이 22개가 실패했다. 이 오래된 검사 실패를 숨기거나 Android 전체 통과로 표시하지 않는다. 현재 검사는 node --test android/tests/r82-wrapper.test.cjs로 실행하며 먼저 R82 HTML을 Android에 준비해야 한다.

## 후속 Android APK 빌드

사용자의 설치용 APK 요청에 따라 Android SDK 36의 공식 platform/build-tools를 설치하고 JDK 21로 R82 APK를 빌드했다. SDK 아카이브는 Google 공식 repository 메타데이터의 크기와 체크섬을 대조했다. 별도 패키지 org.quadrift.mongyu.preview.r82 / 몽유 R82 테스트로 구성해 기존 앱과의 서명 충돌을 피했다. 설치용 테스트 서명 후 APK Signature Scheme v2/v3 검증, 16KB zipalign, ZIP 무결성, 권한 없음, 최종 R82 HTML의 바이트 동일성을 확인했다. 최소 API 26, target API 36이다. evidence/r82-signed-apk.json이 이번 결과이며 위 본문에서 SDK가 없어 컴파일하지 못했다고 적은 내용은 이 후속 빌드 이전 시점의 기록이다. 실제 Android 기기에서 설치하거나 플레이한 결과는 아니다.
