# R93 원작 파일 실행 경로

R92의 자체 캐릭터·녹음곡·각색 대사를 조금씩 바꿔서는 ‘원작과 동일’이라는 목표를 확인할 수 없다. R93은 그 엔진을 APK에서 제외하고 원작 실행 코드와 리소스를 직접 실행하는 경로를 제공한다. 상용 원작 파일은 배포 APK·소스·검사 산출물에 포함하지 않는다. 사용자가 보유한 KTF ZIP/JAR를 한 번 선택하면 파일은 기기 안에 보관하며 서버로 전송하지 않는다.

## 무엇이 달라지는가

캐릭터·모든 포즈·대사·스토리 분기·장애물·배경·카메라·스킨 조건은 선택한 원본 프로그램과 리소스가 결정한다. R92의 벡터 그림·대체 녹음·100개 조건 재해석을 사용하지 않는다. 이 방식은 원본을 재창작해 완전히 같다고 주장하는 것과 구분한다. 원본 저장도 원본 코드가 생성한 WIESAV01 데이터로 별도 보관한다. 기존 몽유의 진행을 원작 수집 진척으로 바꾸거나 삭제하지 않는다.

원본 화면은 240×320 비율을 보존해 화면 안에 맞춘다. 길쭉한 최신 화면에 맞추려고 원작 그림을 늘리거나 HUD를 잘라내거나 카메라를 새로 확대하지 않는다. 화면 탭은 OK, 아래 취소·방향·확인 키는 실제 원작 입력으로 전달한다. 일시정지·앱 전환은 입력을 놓고 엔진 틱과 오디오를 중단한다. 자동 재개하지 않는다.

## 실행기와 소리의 한계

wie 브라우저 실행기의 공개 아티팩트를 핀 고정한다. 소스 커밋 `1ca15ebf5a3ebc691a680a7854e99a32e75d46f4`, WASM SHA-256 `a4a32d289c2281239d2d4e9c00c065d10203fe151969a6f324761e4e3a38ecdf`. MIT·Apache 2.0·Neo둥근모 OFL 고지를 앱에 포함한다. 상용 게임 파일은 실행기와 별개다.

음표·리듬·PCM 효과음은 가져온 원본 MMF가 생성한다. 현재 실행기의 MIDI 렌더러는 원래 휴대폰의 Yamaha 칩을 동일하게 에뮬레이션하지 않는다. 따라서 원작 멜로디와 효과음 데이터를 실행하더라도 음색이 실기와 완전히 같다는 뜻은 아니다. GeneralUser 사운드폰트와 R92의 작곡가 녹음곡은 이 APK에 포함하지 않는다.

원본의 통신사 서버·전화·특정 기기 API에 의존하는 기능, 모든 원본 버전의 동등성, 100개 수집 연속 완주와 모든 동작·실기 음색 대조는 확인해야 한다. 원본 코드를 실행한다는 사실만으로 미확인 기기 API나 전체 100개 완주가 검증됐다고 표시하지 않는다. 실행 속도도 기기에 따라 떨어질 수 있으며 설정 1배속과 실제 달성 속도를 구분한다.

## 파일과 기록

원본 ZIP/JAR를 검사한 뒤에만 보관한다. 최대 파일 16MB, 풀린 총 크기 64MB·512개 항목, CRC·경로·중복·필수 리소스를 검사한다. 원본 JAR만 있는 KTF 파일에는 실행용 컨테이너 정보만 덧붙이며 JAR의 코드·그림·음악·문장은 바꾸지 않는다. 완전한 ZIP의 기존 원본 저장은 그대로 읽고, 새 기록은 원본 파일 지문별로 분리한다.

원본 파일 선택은 Android 시스템 파일 선택기를 사용한다. 광범위 저장소 권한·인터넷 권한은 추가하지 않는다. 파일을 앱의 제한된 내부 저장소에 복사하고 무결성을 확인한 뒤 채택한다. 잘못된 대체 파일은 이전 파일을 덮지 않는다. 저장 저널은 이전 유효 기록을 백업하고, 손상 기록·미래 버전을 조용히 덮어쓰지 않는다.

## 검증 범위

새 플레이어 검사와 과거 각색 엔진 검사는 분리한다. `python3 scripts/test.py`는 현재 플레이어와 자산을 검사한다. 기존 각색 엔진 검사는 `python3 scripts/test-legacy-r92.py`로 남긴다. APK에는 새 플레이어 자산만 넣는다.

브라우저에서 별도로 확보한 원작 후보를 실제로 불러와 원작 로고·메뉴·이야기·게임 입력·오디오·저장·재실행을 검사한다. 검사 결과는 게임 파일·원본 화면·음표 이벤트 대신 개수·해시·상태만 기록한다. Android에서는 실제 시스템 파일 선택기로 같은 후보를 불러와 실행·앱 복귀·업데이트·렌더러 복구를 확인한다. 최종 결과는 검증 후 추가한다.
