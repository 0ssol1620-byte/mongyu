# R88 카메라·발 접촉 재검수

이전 R87의 실행·저장·보스 진행 검사는 화면 표현의 정확성을 충분히 검사하지 못했습니다. 이 기록은 사용자 지적 이후 재현한 표시 오류와 검사 범위를 구분합니다. 네이티브 시뮬레이션 여섯 파일의 기존 무결성 검사는 유지합니다.

## 재현한 오류와 변경

- 일반 카메라는 진행 방향에 따라 캐릭터를 화면 모서리 가까이 옮겼습니다. 방향이 바뀌면 화면의 목표점도 크게 움직였습니다. 표시 중인 캐릭터 몸통의 중심을 화면 중앙에서 추적하도록 바꿨습니다. 캐릭터의 기존 표시 보간을 따르며 두 번째 위치 지연을 더하지 않습니다.
- 역방향 이동의 접선으로 몸 전체를 180도 돌려, 지면 법선까지 뒤집었습니다. 이동 접선과 몸이 서는 법선을 분리해 좌우 반전으로 처리합니다. 개의 표시 방향에도 같은 원칙을 적용합니다.
- 일반 지형의 타일 명령은 회전한 바닥 모서리를, 고정 마스크 지형은 격자 셀의 중심을 제공합니다. 같은 기준으로 그리던 것을 분리했습니다. 마스크 접촉점의 8단위 보정과 일반 주행의 한 셀 안쪽 몸 중심도 표시 좌표에 반영합니다. 게임의 위치나 충돌·점수·입력은 바꾸지 않습니다.
- 평지 보폭은 높이가 다른 계단에서도 그대로 쓰여 발·무릎이 이전 단차나 다음 단차에 들어갔습니다. 화면의 실제 타일을 대상으로 발을 들거나 보폭을 줄입니다. 두 다리 뼈의 길이와 앞을 향한 무릎을 유지합니다. 모서리 사이에서는 접촉 중인 양쪽 벽을 함께 검사합니다.
- 작은 발판과 일반 맵 변형에 갑자기 경기장 전체 카메라가 적용됐습니다. 두 구간도 캐릭터를 추적하고 기존 배율을 유지합니다. 보스·분할 화면은 필요한 경기장 배치를 유지합니다.
- 일반 맵 변형의 캐릭터 캡처에는 아래쪽 16단위가 포함되는데 이를 발로 그렸습니다. 표시 오프셋을 변환하고, 변형 중 실제 그리는 캐릭터를 카메라 목표로 사용합니다.
- 자유 회전 구간은 실제 actor draw의 방향과 좌표 대신 기본 지면 방향을 사용했습니다. 실제 표시 명령으로 연결했습니다.

이 미술·발 디딤·현대 화면비 카메라는 몽유의 표시 어댑터입니다. 원작 스프라이트와 픽셀 단위로 같다는 뜻이 아닙니다.

## 검사 방법과 한계

`node --test web/tests/r88-camera-contact.test.cjs`는 카메라 중심, 정·역방향의 네 벽, 마스크 격자와 다리 중심선, 역방향 공중 회전, 맵 변형·작은 발판·보스·분할 카메라, 계단의 두 관절 길이, 특수 회전 방향, 실제 도달한 중간 모서리 사례를 검사합니다.

`node tools/audit-r88-contact.cjs`는 74개 격리 물리 진입을 seed 7·정오·빠름 설정으로 최대 220 업데이트 실행하며 7 업데이트마다 정상 액션을 입력합니다. 접지 자세 1,867개와 도달한 접지 모서리의 중간 자세 365개에서 다리 중심선이 16단위 타일의 내부 11×11 영역을 통과하는지 검사했고 0개였습니다. 이 검사는 몸 전체·외곽선의 얕은 접촉, 모든 입력·시드·구간, 100개 연속 완주를 증명하지 않습니다.

`node tools/verify-r88-camera-contact.cjs`는 실제 Canvas에 그린 다리 경로와 11개 장면을 검사합니다. 같은 장면을 Android QA에도 추가했습니다. 검사 장면은 격리 실행이며 실제 사용자 진행도를 수정하거나 수집 결과를 지급하지 않습니다.

별도 12초 브라우저 녹화에서 683개 표시 프레임과 정·역방향, 세 지면 방향을 확인했습니다. 해당 실행은 정상 입력으로 216 업데이트까지 진행했고 2 목숨을 유지했습니다. 브라우저 녹화는 Android 실기기 성능 인증이 아닙니다.

발 디딤 초기 구현은 각 후보의 다리 선분을 반복 샘플링했습니다. 성능 검사에서도 긴 프레임이 관측돼 추가 계산량을 줄일 필요가 있었습니다. 선분·타일의 정확한 교차 계산, 다리 도달 범위로 제한한 타일 검사, 불가능한 후보의 빠른 종료로 변경했습니다. 최종 성능·Android 결과는 아래에 별도 기록합니다.

## 최종 성능 재측정

같은 현 시점의 Chromium, 390×844, DPR 상한 1.5, CPU 4배 제한, 별도 부하 없이 순서대로 600 RAF 프레임을 측정했습니다. R88의 프레임 간격 p95는 약 50.7ms, 엔진 계산 p95는 30.4ms였고, 이어서 다시 측정한 R87은 각각 53.7ms·32.8ms였습니다. R88에서도 최대 300.2ms의 긴 프레임이 남았습니다. 화면 정적 속성의 반복 쓰기는 두 실행 모두 0개입니다. 과거 다른 시점의 33.9ms와 단순히 비교해 개선 또는 퇴보 비율을 주장하지 않습니다. 무지연이나 실기기 성능 통과를 뜻하지 않습니다. `r88-sustained.json`·`r88-r87-current-baseline.json`에 원자료가 있습니다.

초기 발 디딤 구현의 측정은 `r88-sustained-prototype.json`에 구분해 보존합니다. 계산 자체는 정확한 선분 교차로 줄였지만, 전체 프레임 지연을 발 디딤의 단일 원인으로 단정하지 않습니다.

최종 배포 HTML의 별도 브라우저 흐름 검사에서는 예외 0개, 오프라인 실행, 10개 스테이지 녹음, 일시정지·재개·의상 재시작 복구·첫 조작 안내 해제·세 화면 크기에서 전체 화면을 확인했습니다. CPU 4배 제한의 명시적 화면 그리기 120회 p95는 2.5ms였습니다. `r88-browser-report.json`은 전체 프레임과 화면 그리기를 구분해 기록합니다.

가속 Android 15 / WebView 124.0.6367.219의 실제 설치 APK에서 기존 실행·입력·전체 화면·일시정지·복귀·저장·복구 8개 항목과 새 시각 검사 묶음이 통과했습니다. 정·역방향의 네 벽, 계단 2개, 특수 회전의 11개 Canvas 장면에서 카메라 중심 오차와 검사한 다리 중심선의 깊은 타일 관통은 모두 0개입니다. 실제 Android 캡처와 보고서는 `r88-android-device.json` 및 `r88-android-*.png`에 있습니다.

업데이트 검사는 현재 코드로 만든 versionCode 87/88 패키지와 임시 QA 인증서를 사용합니다. 실제 R87 APK 자체의 모든 바이트를 재현한 검사가 아닙니다. 배포 APK는 통과한 unsigned 페이로드를 기존 R82 이후 인증서로 서명했고, 서명 메타데이터를 제외한 모든 ZIP 항목이 검사 파일과 같음을 확인했습니다. 서명한 배포 APK 자체의 실기기 설치와 구분합니다.
