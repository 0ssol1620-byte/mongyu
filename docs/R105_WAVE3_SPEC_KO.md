## 작업 CH · 캐릭터 교체 (새 디자인을 게임 안에서)
소유: `web/src/character-art.js`, `web/src/mobile-presentation.js`(`sprite()`의 polish 경로만), `web/tests/r105-char-*.test.cjs`, `web/src/i18n-en-char.js`(필요 시).

현재 게임 속 캐릭터는 벡터로 그린 후드 아이다. **생성한 새 디자인**(머리카락이 보이는 보라색 수면 모자와 흰 방울, 크림색 잠옷, 라벤더 목도리 망토, 둥근 볼. `pose-*` 8장과 곧 추가될 `run-01`~`run-08`)으로 **게임 속 모든 곳의 캐릭터**를 바꾼다.
- `sprite(c,q,fx,reduced,character,style)`의 polish 경로가 래스터 포즈를 그린다. 포즈 선택은 `q.pose`와 기존 필드(`nativeState`, `jumpProgress`, `strideDistance`, `height`)에서 추론: 서기(`pose-stand`), 달리기(`run-01..08`을 `strideDistance` 위상으로 순환, 없으면 `pose-run-a/b` 교대), 점프(`pose-jump`), 착지(`pose-land`), 넘어짐(`pose-hurt`), 기쁨(`pose-joy`), 잠(`pose-sleep`), 벽 달리기(달리기 프레임을 표면 각도로 회전).
- `renderAngle`/`tangent`/방향 반전을 기존과 같게 따라 바닥·벽·천장에 붙어 있어야 한다(천장에서는 뒤집힌다). 달리기 위상은 달린 거리에 비례, 점프/착지는 스쿼시·스트레치로 보강, 망토는 속도에 비례한 약한 기울임(절차적 변형, 반응형). 눈에 띄는 가장자리 번짐(마젠타 잔여)이 없어야 한다.
- 크기: 화면 높이의 약 9%(기존 bodyHeight 규칙 유지), 그림자와 네온 림라이트(현재 챕터 팔레트의 `rim`색, `MongyuTrip.get(q.trip||'violet').rim`)를 얇게 더해 환각 배경에서 분리되게.
- **옷장(스킨):** 기존 `look()`/`style`의 색 의미를 모자·망토 색조 변형으로 매핑(오프스크린 캐시 위에 `hue`/`color` 합성, `ctx.filter` 금지), 선택한 옷이 실제로 바뀌어 보여야 한다. 스킨별 캐시.
- NPC(`elder`, `woman` 등)는 기존 벡터를 유지하되 팔레트를 어두운 환각 톤과 어울리게 조정해도 된다.
- 성능: 캐릭터 한 번 그리기 ≤ 0.3 ms(스프라이트 디코딩 후), 프레임당 할당 최소화. 이미지가 아직 디코딩 중이면 기존 벡터로 그린다.
- 검증: 모든 act(바닥·벽·천장, 착시 다리, 나선, 펜로즈, 정렬), 이야기 장면, 로비(`lobby-scene.js`는 소유하지 않으므로 `MongyuMobile.sprite` 호출 규약만 지킨다), 결과 화면에서 확인. 달리기 사이클이 부드러운지 프레임 시퀀스로 본다.

## 작업 MU · BGM 2.0
소유: `web/src/adaptive-music.js`, `web/src/game-sfx.js`, `docs/R105_BGM_BRIEF_KO.md`(신규), `web/src/i18n-en-music.js`(필요 시), `web/tests/r105-music-*.test.cjs`.

지금 음악은 Web Audio 합성(4층 적응형)이다. **더 좋게**: 사이키델릭하고 몽롱하며 중독적인 소리, 놈3처럼 **심장 박동 기반 리듬**(저음 맥박)과 시각 맥동의 동기.
- **음색 고도화:** 가야금(Karplus–Strong + 공명), 해금(활 마찰 모델 + 비브라토), 대금(공기 소음 + 도약), 장구/북(피치 하강 막 타악)의 모델을 개선. 두툼한 디튠 패드, 천천히 도는 필터, 위상/코러스, 긴 리버브, 반전 리버브 스웰, 아르페지오 시퀀서(결정적).
- **착시 음향(핵심 아이디어):** 펜로즈·나선 구간의 시각 착시에 대응하는 **청각 착시** — 끝없이 오르는 **시퍼드(Shepard–Risset) 글리산도**(오르막/펜로즈), 내려가는 글리산도(내리막). 소리가 높아지는데 음역은 제자리인 느낌.
- **구조:** 코스마다 인트로→A→B→절정→해소의 매크로 구조(반복 티가 덜 나게 화성 이동·변주·드롭아웃), 박자 격자(`chain.bpm`/`MongyuAdaptiveMusic.bpm`)와 정확히 동기(장애물 시점 = 박자), 챕터별 음계·BPM·정체성(1장 보라: 느린 몽롱한 맥박 90–100 BPM, 2장 심해: 물방울과 긴 잔향, 3장 잉걸: 리듬 강조, 4장 독성: 불협에 가까운 긴장과 해소, 5장 맥박: 심장 박동 템포를 점점 올림).
- **적응:** 콤보와 거리에 따라 층, 충돌 시 필터 닫힘, 아이템 획득 시 조성에 맞는 음, 오로라 파도(surge) 때 화려한 층, 실패 후 재시작 시 자연스러운 복귀. 장면 전환(오로라 문)에서 매끄럽게 이어짐.
- **효과음:** 현재 key에 맞는 음. 아이템별 고유 소리(방울: 맑은 종, 시간: 느려지는 하강음, 깃털: 상승 글리산도, 별: 반짝이는 아르페지오), UI 소리 다듬기.
- **객관 검증(귀가 없으니 숫자로):** 오프라인 렌더로 챕터 5곡을 렌더해 피크 ≤ -1 dBFS, 통합 라우드니스(근사 LUFS) -16~-20, 스펙트럼 균형(저/중/고 대역 에너지 비율), 클릭·DC·클리핑 없음, 루프 길이, 스테레오 폭을 `docs`나 보고서에 표로. 소리가 **직접 들어 보지 못했다는 점을 보고서에 명시**하고, 사람 귀로 확인할 체크리스트를 적는다.
- **의뢰서:** `docs/R105_BGM_BRIEF_KO.md` — 작곡가에게 줄 브리프(참고 작품 방향: 시각·소리가 하나로 묶이는 사이키델릭 리듬 게임들, 한국 전통 악기를 쓰는 앰비언트·실험 음악, 몽환적 모바일 게임 사운드트랙의 구조. 특정 곡을 복제하지 말 것), 챕터 5곡의 분위기·키·BPM·층(스템) 요건, 루프와 파일 사양(44.1kHz, 루프 포인트, 스템 분리), 권리(buyout, 사운드트랙 발매 포함) 항목. 합성 음악은 임시본임을 명시.
- 성능: 동시 목소리 ≤ 48, 오디오 스레드 부하가 낮게(스케줄링은 기존 선행 스케줄러 방식 유지).

## 작업 CP · 챕터 2~5와 새 act
소유: `web/src/chapters.js`(신규), `web/src/course-run.js`(챕터 정의·진행 관련 부분만; **다른 에이전트(TR)가 같은 파일의 전환/HUD 색 부분을 고치므로 해당 함수 밖에서만**), `web/src/road-mode.js`(챕터 선택 UI·잠금 로직), `web/src/endless-dream.js`(act 래퍼), 새 act 파일 `web/src/square-act.js`(신규, 작업 CP 전용), `web/css/r104-road.css`(챕터 UI의 **레이아웃**만), `web/src/i18n-en-chapters.js`(신규), `web/tests/r105-chapters-*.test.cjs`. `web/sources.json`에 신규 파일을 등록한다(`chapters.js`는 `course-run.js` 앞, `square-act.js`는 `course-run.js` 앞).

(b) 하나 더: 예를 들어 `flip`(중력 뒤집기 복도), `mobius`(바닥↔천장 연속 뫼비우스), `tube`(원통 내부 360° 달리기) 중 구현 가능한 것을 골라 **새 메커닉**으로 만든다. 모든 새 act는 `registerAct`로 등록하고 act 계약(`chain`, `items`, `hud`, `trip`, 결정성, 이벤트 이름)을 지킨다.

- **이야기:** 챕터마다 짧은 인트로 1~2줄과 엔딩 1줄(1인칭 독백 반말, `docs/R105_VOICE_TONE_KO.md`), 챕터 헤더와 결과 패널에 표시.
- **기록 저장:** 기존 `mongyu.r105.road` 형식과 호환되게 코스 id별로 확장(`c1`~`c5`는 그대로, 새 id는 `c6`~`c25`).
- **검증:** 모든 새 코스를 자동 조종으로 끝까지 클리어(act별 조종 로직을 `roadplay.mjs`에 추가: `square`·새 act용), 클리어 시간과 난이도 곡선(별 조건 달성 가능성)을 표로 보고.

## 작업 LB · 로비 재조정 (새 어두운 로비 이미지)
소유: `web/src/lobby-scene.js`, `web/src/lobby-ui.js`, `web/css/r104-ui.css`, `web/src/i18n-en-lobby.js`, `web/tests/r105-ui-lobby.test.cjs`.

로비 배경 이미지가 **`lobby-trip`**(어두운 블랙라이트 보라, 달항아리 달 안에 이미 만다라가 있음, 아래쪽 1/3은 어두운 호수로 버튼 자리)으로 바뀌었다. 이전 이미지(`lobby-psy`, 무지개, 속이 빈 흰 달)에 맞춰 만든 **달 안의 소용돌이 장면은 제거**하고, 새 이미지에 맞게 다시 만든다. `lobby-psy` 사용은 모두 `lobby-trip`으로.
- 달항아리 위치·크기를 새 이미지에서 측정해(중심 약 상단 중앙) 그 주변에 **보라/마젠타 계열 동심원 파문과 천천히 도는 만다라 링**(절차적, 색은 `MongyuTrip.get('violet')`의 rim/rim2/glow, 알파 낮게)과 항아리의 **호흡하는 글로우**(주기 ≥ 6초, ±6%)를 얹는다. 이미지 속 눈을 천천히 깜빡이는 위치별 오버레이, 보라/청 계열 입자(무지개 금지).
- 캐릭터(`MongyuMobile.sprite`, 새 디자인으로 곧 교체됨)는 호수 위 작은 돌판 또는 징검돌 위에 서서 숨 쉰다(위치는 이미지 구도에 맞게 재선정). 달 쪽으로 이어지는 계단의 시선 방향이 CTA와 겹치지 않게.
- **로고 "몽유":** 무지갯빛 그라데이션을 버리고 **보라→마젠타(2색) 네온 그라데이션 + 시안 포인트 윤곽**(고정, 순환 없음), 얇은 글로우. CTA/도크 패널의 무지갯빛 테두리도 **보라→마젠타** 한 계열로.
- 하단은 호수의 어두운 영역이므로 CTA와 도크가 선명하게 읽힌다. 320×568, 가로 844×390 레이아웃 재확인. 안전 규칙 준수(`reduced` 정지, 밝기 변화 측정).
- 검증: 로비 스크린샷 3사이즈, 프레임 시퀀스로 움직임이 느리고 안전한지, 모든 로비 동작(CTA → `MongyuRoad.nextCourseId()`가 있으면 그 id, 없으면 기존 `nextCourseId()` 로직, 도크 5개, 다른 꿈 시트).
