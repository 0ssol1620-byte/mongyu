# R86 재점검: 끊김, 확대, 표시 누락

R85는 원작 전체 복원이 끝난 상태가 아니었습니다. 기존 슬롯 검사가 초기 12번 업데이트에 머물렀고, 엔진의 시작 카운트다운 30회가 끝나기 전이라 실제 이동 이후를 충분히 검사하지 못했습니다. R85의 직선/코너 기준 9% 확대도 원작 확인 없이 넣은 몽유용 연출이었습니다.

## 발견하고 수정한 문제

| 문제 | 원인 | R86 변경 |
|---|---|---|
| 계속 확대된 화면 | 작은 경기장을 높이에 맞춰 크게 채우고, 직선에서 추가 확대 | 추가 확대 제거. 점프나 바운드 크기에 흔들리지 않는 배율로 더 넓게 표시. 화면 배경은 계속 전체 크기로 그림 |
| 주기적인 실제 계산 지연 | 각 엔진 단계마다 큰 숫자 배열을 문자열 키로 다시 열거하고 복사 | 밀집 배열 복사 경로를 개선하고, native tick 내부에서 완성된 캡처의 동결 복사본을 공유. 캡처를 쓰는 단계와 외부 체크포인트는 독립 복사. 순환/별칭/희소 배열/특수 값 fallback 유지 |
| 이동 중 UI 작업 지연 | 점수가 바뀔 때마다 숨김, 버튼, 접근성 속성을 다시 기록 | native 플레이 전용 상태 캐시. 점수·힌트 변경과 화면 전환만 반영 |
| 발이 멈추거나 미끄러지는 동작 | 엔진 화면 이동으로 상쇄된 좌표를 실제 이동 거리로 사용 | native 카메라 변환량을 보정한 물리적 이동 거리로 보간/달리기 동작 계산 |
| 벽에서 정지한 것 같은 동작 | 벽 동작 state 12에도 달리기 포즈만 사용 | 기록된 동작 프레임에 따른 벽 자세. 충돌과 원래 동작 시간은 바꾸지 않음 |
| 중간 맵 전환이 정지 화면처럼 보임 | 엔진의 캡처 셀과 보간 명령을 표시하지 않음 | 실제 old/new 캡처 좌표로 셀 이동. native tick 사이도 보간하고 일시정지 시 화면을 동결 |
| 다중 화면 구도 소실 | actionLock에 따른 분할 clip/actor 선택을 무시 | 실제 명령별 clip·셀·배우 표시를 연결. 3/4/17/20 모드 검사 |
| 보스 형태 소실 또는 단순화 | 플레이용 geometry만 그리고 보스 셀 명령을 무시 | 10개 보스의 실제 기능상 셀 윤곽·프레임을 표시 |
| 반격·시작 반응 누락 | state 11 입자/카운트다운 명령이 UI에 연결되지 않음 | native 입자와 반격/시작 효과음 연결. 근거 없는 획득 아이템이나 확대는 만들지 않음 |
| 특정 설정에서 생성 중단 | 장애물 위치 조정이 동일 위치를 반복해 예외 반환 | 반복이 검출된 경우에 한해 가장 가까운 유효한 비충돌 위치로 이동. 점수·아이템·클리어를 지급하지 않음 |

마지막 생성 복구는 원작 동등성이 아닌 몽유의 안정성 수정입니다. 복구는 유효한 바닥/배우 충돌 검사를 통과한 위치만 고르고 추가 난수를 사용하지 않습니다. 나머지 엔진 본문은 기존과 동일하며 복사 연결, 읽기 전용 파라미터 공개, 이 한정 복구 연결만 무결성 검사에서 명시적으로 구분합니다.

## 검사 재현

- `python3 scripts/test.py`: 최종 단일 HTML 빌드/해시/이식성과 웹 테스트. 복사 동등성과 명령 제거 동등성 검사를 64회 업데이트까지 늘려 카운트다운 이후도 비교합니다.
- `node tools/audit-runtime.cjs`: 100개 항목 분류, 74개 native 후보 항목을 seed 7/19로 최대 420회 실행. 사용자 저장을 수정하지 않습니다. 정상 액션 입력만 사용하며 종료 실패도 조건에 따라 정상 결과로 기록합니다.
- `node tools/audit-native-patterns.cjs`: 원래의 256개 숫자 행을 명시적인 provider로 각각 선택. 제어된 설정 검사이며 정상 수집/완주 증거와 구분합니다. 과거 중단 행 36의 재현과 복구를 검사합니다.
- `node tools/audit-boss-exits.cjs`: 명시적으로 격파 직후 상태를 만든 제어된 10개 보스의 산개/확인/결과 경로 검사. 정상 입력 격파와 구분합니다.
- `node tools/verify-r86-renderer.cjs`: 최종 브라우저 번들의 첫 달리기/개/10개 보스/실제 캡처 전환/반격/4개 분할 모드 화면을 확인합니다.
- `node tools/verify-sustained.cjs R86`: 시작 직후 120프레임을 넘겨 600프레임 동안 측정. 데스크톱 CPU 4배 제한은 실제 Android 성능을 보증하지 않습니다.
- `node --test android/tests/r82-wrapper.test.cjs`: 현재 앱의 back/pause/저장 계약. 이전 역사적 R31 wrapper 테스트와 혼동하지 않습니다.

전체 100개 정상 입력 완주, 원작 전체 영상/자산 대조, 실제 Android 휴대폰의 장시간 성능·발열·터치 검수는 미완료입니다. 이 빌드를 ‘원작 모든 콘텐츠 복원 완료’ 또는 ‘모든 버그가 없다고 증명됨’으로 표시하지 않습니다.

## 최종 결과

- 웹 140개 중 139개 통과, 외부 어댑터 1개 생략. 현재 Android 콜백 VM 검사 5개 통과.
- 148회 진행 검사에서 중단/비유한 좌표 오류 0건. 49회는 독립 실행에서 조건을 채워 종료했으며, 캠페인 100개 정상 완주와 구분합니다.
- 제어된 256개 설정 검사에서 중단 오류 0건. 과거 반복 행 36도 통과합니다.
- 실제 native 스냅샷 19장면(첫 달리기, 개, 보스 10개, 전환, 반격, 부유, 분할 4종)의 브라우저 표시와 오프라인 실행 확인.
- CPU 4배 제한의 600 RAF 프레임에서 R86 프레임 간격 p95 33.1ms, 최대 127.2ms. 50ms 이상 long task 7회. 시작 전후 단기 120프레임 p95는 24.7ms였습니다. 드문 긴 프레임이 남아 있으므로 무렉을 보증하지 않습니다.
- 같은 계측 절차의 R85 관측은 p95 143ms, 최대 1115.5ms였습니다. 단, 600프레임 동안 실제 진행한 native 업데이트 수가 각각 144/292로 달라 동일한 시뮬레이션 경로의 일대일 벤치마크는 아닙니다. DOM/long-task 관찰기를 붙인 데스크톱 측정이며 실제 휴대폰 수치로 환산하지 않습니다.
- 계측 중 비교한 정적 버튼/캔버스 속성의 반복 갱신은 R86에서 0회였습니다. 캡처 버퍼 공유는 외부 체크포인트의 독립성과 실제 전환 이후의 유효성을 검사합니다.

기계 판독 요약은 evidence/r86-verification-summary.json, 항목별 구분은 evidence/r86-content-inventory.json에 있습니다. 현재 APK의 바이트/서명/정렬/최종 HTML 일치는 evidence/r86-signed-apk.json에서 확인할 수 있습니다.

## APK

R86은 versionCode 86, 0.86.0-preview, Android 8.0 이상용 테스트 APK입니다. 앱 ID org.quadrift.mongyu.preview.r82와 기존 서명 키를 유지합니다. 기존 앱을 지우지 않고 업데이트하면 저장을 유지할 수 있습니다. 프로덕션 스토어 서명이나 출시 완료를 의미하지 않습니다.
