# R87 원작 재조사와 진행 차단 수정

## 직접 확보한 근거

2026-11-15 공개 검색을 통해 [KTF판 보관 게시물](https://dubigame.tistory.com/16)의 자료를 내려받아 개인 분석용 작업 경로에서 확인했습니다. JAR의 SHA-256은 `aeadd87840c7b3f1f06548489406dbc0bf833b41de9cdfa3eaf741e832a213c2`, 실행 바이너리는 `782b2c836ef32331e74a943367aa7bae09891fa56ca39cd89acfa887bcfa55d3`로, 기존 기능 추출 후보와 같습니다. 제삼자 보관 파일이므로 공식 배포본의 진위나 모든 기종의 동등성을 보증하지는 않습니다.

[2008년 당시 플레이 캡처](https://blog.yuptogun.com/280), [100판 완주 기록](https://github.com/suapapa/blog/blob/c38208917963b7ea45dd3fd114a465e5e8f4f249/content/post/2008-01-29-%EA%B2%8C%EC%9E%84-%EB%86%883-%EC%A0%95%EB%B3%B5.md), [제작자 인터뷰](https://www.gamemeca.com/view.php?gid=65877)도 대조했습니다. 최신 [피처폰 에뮬레이터 지원 목록](https://featurephone.otterpebble.com/support/8c8b11508cf5)은 놈3 실행을 명시하지만 상용 게임 파일을 제공하지 않습니다. 조사 과정에서 해당 사이트를 원본 파일 제공처로 취급하지 않았습니다.

원본 JAR·실행 파일·스프라이트·대사 파일·녹음은 APK와 소스 배포에 포함하지 않습니다. 파일별 목록과 해시는 `evidence/r87-original-file-audit.json`에 있습니다. 별도로 확보한 동일 후보로 `python3 tools/audit-original-fields.py <research.jar>`를 실행해 필드와 숫자 팔레트를 재검사할 수 있습니다.

## 확인한 결함과 변경

| 영역 | 확인한 문제 | 수정 |
|---|---|---|
| 보스 반격 | 작은 반사체에 `y.c=3`을 써야 하는데 `y.l=3`으로 이식됨. 수명이 3회로 덮여 원거리 보스에 도달하기 전에 소멸 | 원래 표시 필드 `c`에 기록. 기존 수명 15회, 특정 보스 23회를 보존. 임시로 수명을 늘리는 별도 규칙은 최종 코드에서 제거 |
| 보스 회복 | 타이머가 이미 0인 프레임에 피격 상태 Y를 해제하는 분기가 누락. 특히 77/99번은 첫 피격 뒤 영구 무적 | `0x55c6c → 0x56f20 → 0x55c8a` 분기를 복구. 0 타이머 진입 시 Y=0, 남은 타이머는 기존 감소 순서 유지 |
| 배경 | 엔진이 만든 `semantic-background` 명령을 화면에서 버리고 자체 무늬만 표시 | 일반 64개/보스 256개 실제 배경 셀, 반사 위상·명암·피격 회색·배경 채움 연결. 100개 레코드의 RGB와 접힘 색상 인덱스 연결 |
| 화면 크기 | 원래 배경 정사각형 밖의 긴 휴대폰 영역 | 정사각형 타일의 비율을 유지하면서 화면 끝까지 연장. 이는 현대 화면비를 위한 몽유의 표시 확장 |
| 표시 비용 | 배경 셀을 모든 표시 프레임마다 다시 그릴 가능성 | 엔진 스냅샷별 작은 오프스크린 배경 캐시. 표시 프레임에는 캐시만 합성 |
| 캐릭터 | 검은 타일 위에서 검은 팔다리가 사라짐 | native 화면에서 가는 밝은 윤곽선 추가. 캐릭터 그림과 관절 리그는 몽유용 |
| 음악 선택 | native의 실제 `u.ax`를 무시하고 슬롯의 10단위 묶음을 사용 | 실제 곡 번호 사용. 추가 난수 없음. 카운트다운·맵 변형·보스 종료에는 재생을 쉬고 정상 재개 시점에 연결 |
| 효과음 | 보스가 맞아도 체력 변화에 따른 소리가 없음 | 같은 보스의 실제 체력 감소에 한 번만 반응. 재시도·보스 교체의 이전 상태를 재사용하지 않음 |

반격 필드 검증: 바이너리의 상대 슬롯 표 시작은 `0x70260`입니다. `y.l` 읽기/쓰기 토큰은 `0x012c00a7`, `y.a`는 `0x012c0091`, `y.i`는 `0x012c00a1`, 작은 셀에 3을 쓰는 대상은 일반/공중 전투 모두 `0x012c0095`로 `y.c`입니다. `0x42896`과 `0x434be`의 즉시값 3도 재검사했습니다. 기존 해시 검사는 이 한 줄의 확인된 정정을 명시적으로 구분하며 나머지 엔진 변경을 숨기지 않습니다.

Android 실행 검사에서 추가로 확인한 WebView 렌더러 종료도 처리합니다. 종료된 인스턴스를 폐기하고 한 번만 자동으로 화면을 다시 만들며, 반복 종료 시에는 둥근 “다시 열기” 버튼으로 사용자가 재시도를 선택합니다. 저장소를 비우지 않고 앱 프로세스 전체의 강제 종료와 무한 재시작을 방지합니다. 진행 중이던 시도의 메모리 상태까지 복원한다는 뜻은 아닙니다.

Android 가속 검사에서 APK 교체 직후 Web Storage의 최근 쓰기가 없어지는 현상도 재현했습니다. 게임이 소유한 `mongyu.`·`mongyu-`·`quad-rift` 키는 제한된 네이티브 저장 창구로 기록하며, 디스크 쓰기 성공을 확인한 뒤 저장 완료로 처리합니다. 기존 브라우저 기록은 처음 읽을 때 이전하고, 삭제 표식으로 오래된 복사본의 부활을 막습니다. 창구는 읽기·쓰기·삭제만 제공하며 키 길이·키 개수·개별 값·총량을 제한합니다. 외부 탐색·네트워크·파일 접근은 차단하고 패키지에 포함된 페이지에만 사용합니다. 일반 브라우저의 Storage API는 수정하지 않습니다. 초기 문서가 아직 없는 시점의 화면 여백 전달도 안전하게 건너뜁니다.

## 원작 콘텐츠의 확인 범위

후보에는 일반 스테이지용 음악 10개 외에도 보스·타이틀·메뉴·스킨·이야기 음악과 개별 효과음이 있습니다. 현재 APK는 자체 제작 12곡과 합성 효과음을 사용합니다. 원작의 전체 음원 복원이나 원문 대사·원본 캐릭터 스프라이트 복원이라고 표시하지 않습니다. 원작의 수집 스킨과 현장 획득 아이템, 특정 아이템과 카메라 확대의 연계도 구분합니다. 아이템을 먹으면 확대된다는 근거가 확정되지 않았으므로 임의의 상시 확대를 다시 추가하지 않습니다.

100개 항목, 74개 물리 항목의 분류와 R86 검증 범위는 [이전 감사 기록](R86_AUDIT_KO.md)에 보존합니다. 실제 기본 UI의 72개 native 플레이/26개 장면/2개 로컬 전화 각색은 그대로입니다. 원작 배경 색과 숫자 타일 배치는 이번에 대조했지만, 원본 스킨 그림 100종을 모두 재현한 것은 아닙니다.

## 검증 기준

보스 검사는 체력·위치·점수·진행을 고치지 않고 `action()` 입력과 정상 시간 진행으로 수행합니다. `web/tests/r87-normal-boss-inputs.json`은 재생 가능한 입력 기록입니다. 격파 후 원래 종료 애니메이션과 확인 탭을 거쳐 유효한 수집 결과가 나오는지도 검사합니다. 개별 조우 재생은 100개 항목의 처음부터 끝까지 연속 완주와 다릅니다.

Android 패키지 ID와 서명 키는 R82 이후와 동일하며, R87 테스트 APK로 업데이트할 수 있습니다. 가상 기기 검사는 실제 휴대폰 성능 검사와 구분합니다. 실제 결제·광고와 스토어 출시는 비활성입니다.

현재 컨테이너의 Android 15 x86_64 에뮬레이터는 KVM 없이 소프트웨어로 실행했습니다. 시스템 앱의 ANR과 내장 WebView의 네이티브 SIGTRAP이 반복되어 여기서 게임 완주나 실기기 성능 통과를 주장하지 않습니다. R86에서 렌더러 종료가 앱 프로세스까지 전파되는 것을 확인했고, R87의 복구 콜백을 추가했습니다. 별도 GitHub 검사에서는 하드웨어 가속 에뮬레이터와 실제 설치 APK로 다시 검증하도록 구성합니다.

### Android 검사 환경

Google APIs 이미지 검사에서는 Pixel Launcher의 ANR 대화상자가 게임 위에 떠 뒤로 가기 입력을 가로막았습니다. 실패한 [실행 기록](https://github.com/0ssol1620-byte/mongyu/actions/runs/43666427031)과 `r87-android-google-image-failure.json`을 보존하며 통과로 처리하지 않습니다. 오프라인 게임의 다음 검사는 Google 서비스가 없는 같은 API 35 AOSP 이미지에서 실행합니다. 실패 시 앱 상태·시스템 포커스·기기 캡처도 남깁니다.

AOSP 첫 검사에서도 부팅 직후 Pixel 6 오버레이가 적용되며 Activity가 다시 만들어져 초기 검사 연결이 끊겼습니다. 해당 [실패 기록](https://github.com/0ssol1620-byte/mongyu/actions/runs/43667053409)은 `r87-android-first-boot-failure.json`에 보존합니다. 이후 검사는 일회성 시스템 패키지·화면 구성 준비를 20초 기다린 뒤 APK를 설치합니다. 게임 플레이 중 지연을 통과로 바꾸거나 실패를 삭제하는 처리는 없습니다.
