# R89 검수 기록

미술·음악 기획 근거는 [리서치와 적용](R89_ART_SOUND_RESEARCH_KO.md)에 있다. 이번 변경은 자체 벡터 미술과 음악, 화면비 대응이다. 원작 상용 그림·음원·대사 전체의 복원 완료를 뜻하지 않는다.

## 실제 그린 캐릭터 검사

이전 다리 검사는 뼈대 선분과 지형을 비교했다. 새 인물은 가늘어지는 채움형 윤곽이므로 뼈대만으로는 발끝·피부의 겹침을 검출할 수 없다. 기존 선분 검사를 유지하고 실제 Canvas의 다리 채움 픽셀 검사를 추가했다. 숨긴 선이나 별도 대체 모델을 그려 검사하지 않는다.

`node tools/audit-r89-filled-contact.cjs`는 74개 격리 진입을 정오·빠름·7 업데이트마다 정상 액션으로 최대 220 업데이트 실행한다. 실제 다리 윤곽을 단위당 2픽셀로 그려 알파 128 이상 픽셀을 16단위 지형 내부 11×11과 비교한다. 접지 1,867개, 도달한 중간 코너 365개에서 관통 0개였다. 공중·변형·보스·분할 화면, 모든 가능한 입력이나 몸 전체를 인증하는 검사가 아니다.

초기에는 세 계단 자세에서 윤곽의 아주 작은 겹침을 추가로 발견했다. 접지 검사 여백을 조정한 뒤, 다른 오목한 코너의 발끝이 더 큰 화면 배율에서 겹치는 경우도 찾아 발끝 윤곽을 수정했다. `tools/verify-r89-art-contact.cjs`는 정·역방향 네 벽, 계단, 특수 회전 및 이 회귀 사례를 포함하는 15개 실제 화면에서 다리를 단위당 화면 3픽셀로 다시 검사한다. 관통 0개, 몸 중심 카메라 오차 0, 브라우저 예외 0개였다. 알파가 매우 낮은 가장자리 접촉까지 없다고 주장하지 않는다.

12초 실제 브라우저 녹화는 정상 입력으로 세 지면 방향과 양쪽 이동 방향을 지나 220 업데이트, 2목숨을 유지했다. 719개 표시 프레임을 기록했다. 촬영한 실행은 캠페인 전체 완주가 아니며 Android 실기기 프레임 인증도 아니다.

## 화면·소리·성능

단일 HTML의 오프라인 실행, 의상 저장·재시작 복원, 이야기→해금→실제 플레이, 일시정지·재개, 844×390·320×568·800×1280 화면에서 전체 화면 영역을 확인했다. 배경 깊이층은 실제 지형과 구분하고 충돌이나 진행도를 만들지 않는다. 이야기 장면은 실제 배경 색에 맞는 인물 명암을 사용한다.

음원 15개를 모두 FFmpeg로 디코딩하고 해시·스테레오·길이·EBU R128 음량 및 true peak를 기록했다. 새 편곡 14곡은 -20..-16 LUFS와 true peak -1 dBFS 이하 기준을 통과했다. 이는 휴대폰 스피커 청음이나 주관적 음악 품질 검증을 대신하지 않는다. 음악 전환 테스트는 다음 곡이 실제 시작할 때까지 기존 곡을 유지하고, 음소거 뒤 늦게 완료된 재생 요청이 다시 소리를 내지 않는 것도 확인한다.

같은 현 시점 Chromium, 390×844, DPR 상한 1.5, CPU 4배 제한으로 R88과 R89를 순서대로 600 RAF 프레임 측정했다. 최종 HTML의 프레임 p95는 R88 47.7ms, R89 36.5ms, 최댓값은 각각 265.1ms·85.7ms였다. 엔진 계산 p95는 36.3ms·18.0ms였다. 앞선 미술 검토 시점의 동일 절차에서는 p95 37.2ms·33.6ms, 최댓값 101.9ms·114.5ms였고 해당 기록도 `*-initial-art.json`으로 보존한다. 측정 변동이 있고 긴 프레임이 남아 있으므로 미술 변경이 렉을 완전히 없앴다고 표시하지 않는다. 별도 명시적 그리기 120회 p95는 3.4ms였다. 원자료는 `r89-sustained.json`, `r89-r88-current-baseline.json`, `r89-browser-report.json`에 있다.

## Android·배포

[최종 GitHub 검사](https://github.com/0ssol1620-byte/mongyu/actions/runs/43688251721)는 런타임 커밋 `9dfe576465f62b8fb21d72bcd21015a90d6338f8`에서 통과했다. 웹 168개 중 167개 통과·외부 어댑터 1개 제외·실패 0개이며 Android 래퍼 검사 5개도 별도 통과했다.

가속 Android 15 / AOSP WebView 124.0.6367.219에서 실제 APK의 실행·입력·전체 화면, 네이티브 뒤로 가기와 백그라운드 복귀, 업데이트 저장 유지, 최초 렌더러 종료의 복구, 반복 종료의 네이티브 재시도 화면과 저장 복구를 확인했다. 같은 설치 APK에서 15개 실제 Canvas 장면의 몸 중심 오차와 다리 픽셀의 검사한 관통은 모두 0개였다. `r89-android-device.json`과 `r89-android-*.png`가 근거다.

이전 검사 한 차례는 에뮬레이터의 Quickstep 런처 ANR 대화상자가 시스템 뒤로 가기를 가로채 실패했다. 해당 화면과 로그에서 런처를 원인으로 구분했으며 앱의 뒤로 가기 코드를 바꿔 통과시킨 것이 아니다. 최종 검사는 이 대화상자 없이 전체 시스템 입력·복귀 검사를 통과했다.

업데이트 검사는 현재 코드로 만든 versionCode 88/89 패키지와 일회용 CI 인증서를 사용했다. 실제 R88 APK의 모든 바이트를 재현한 검사가 아니다. 최종 unsigned 파일 SHA-256은 `61e26dca3c9f06cba2fff3bd4502ca3aacb04e0ad32558b951a76690ce4ff0dd`이다. 배포 APK는 이 파일에 기존 인증서로 서명했고 서명 메타데이터 외 모든 ZIP 항목의 바이트가 같음을 확인했다.

[몽유 R89 APK와 소스](https://github.com/0ssol1620-byte/mongyu/releases/tag/r89-preview). APK SHA-256은 `a77fef5edc199af7219934c5d853cef50cf225dd7278466be9a5a766231ab732`이다. 앱 ID와 기존 테스트 인증서를 유지하며 versionCode 89, 최소 Android 8.0이다. 실제 휴대폰 장시간 성능·청음과 최종 서명 APK 자체의 실기기 설치를 인증한 것은 아니다. 실제 결제·광고와 스토어 출시는 활성화하지 않는다.
