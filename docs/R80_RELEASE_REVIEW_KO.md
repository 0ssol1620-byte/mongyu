# 몽유 R80 구현·복원·출시 검토

작성: 2026-11-14. 판정: 플레이 가능한 개발 빌드. 상용 출시 승인은 별도다.

## 2. 놈3를 완벽히 복원했는가

**아직 완벽 복원이라고 판정할 근거가 없다.** 100개 슬롯과 10개 보스를 갖췄다는 사실은 모든 원작 동작·표현의 동일성을 증명하지 않는다.

최신 후보에서 분류한 100개 슬롯은 일반/조건 달리기 64, 이야기 17, 인물 4, 보스 10, 짧은 삽화 5개다. 기존 엔진에는 후보 바이너리에서 복구한 수치·제어 흐름과 독립적으로 작성한 브라우저 어댑터가 섞여 있다. 원본 이미지·대사·음원을 모두 재현한 제품이 아니다. 전화 중단 등은 자체 시뮬레이션이고, 원본 기기·통신사별 버전의 차이도 남아 있다.

복원 완료 판정에는 각 슬롯마다 원작 빌드 식별, 초기 상태, 입력 시각, 위치·점수·충돌·해금 결과, 실제 영상 비교가 필요하다. 소스 테스트의 성공을 원작 실기기 동등성으로 바꾸어 표현하면 안 된다. 상업 제품은 몽유의 자체 미술·음악·서사로 완성하되, 복원 연구와 새 제품의 연출 목표를 혼동하지 않는 편이 낫다.

## 3. 검증 결과와 한계

- 최종 배포 HTML을 생성하고 43개 소스의 단일 포함, 음원/이미지 해시 및 오프라인 정책을 확인했다.
- 이 체크아웃의 최종 자동 검사: 101개 중 100개 통과, 실패 0, 생략 1. 생략은 배포하지 않는 외부 감사 어댑터 검사이며 게임의 마스크 소스/인라인 검사는 수행한다.
- 배포 HTML 자체를 로드해 옷장 착용·재시작 복구·잠긴 의상 방어·저장 불가·첫 이야기·기억 해금·네이티브 달리기·지연 프레임·백그라운드/복귀·3곡 역할을 검사했다.
- 기존 PC R79 기반 전체 740개 회귀 검사도 실행했다. 첫 실행은 729 통과/7 실패/4 생략이었다. 실패는 버전 2건, 변경한 연출 기본값 2건, 이전 생성 HTML을 읽던 검사 3건이었다. 이후 해당 기대값과 현재 배포본을 확인하는 집중 검사에서 해결했다. **최종 740개 전체 재실행 통과로 표현하지 않는다.**
- 브라우저에서 390×844의 타이틀·옷장·이야기·꿈 지도·실제 달리기를 관찰했다. 전체 지도 축소로 캐릭터가 작아지던 문제를 따라가기 카메라로 개선했다.
- Android 실기기의 장시간 프레임·발열·배터리·사운드 청취·전화/알림 복귀, 100개 슬롯 정상 입력 완주, 스토어 결제/광고는 통과하지 않았다. 오디오 합성과 파일 분석은 실제 청음 평가를 대체하지 않는다.

## 4. 플레이 경험과 제품 운영

처음 30초에는 조작 하나와 즉각적인 성공을 전달한다. 첫 이야기 다음 단계는 일반 튜토리얼이며, 과금 안내를 표시하지 않는다. 실패하면 같은 조건으로 다시 시도할 수 있어야 한다. 성공 후 새 기억을 얻는 순간을 짧게 보여 주고 다음 꿈으로 이어진다.

장기 목표는 100개의 기억과 변화하는 여행자의 모습이다. 이미 기본 12종 보상이 작동한다. 같은 형태를 색만 바꾼 100종으로 광고하기보다, 실루엣·소품·잔상·움직임이 구분되는 소수의 좋은 의상을 먼저 만든다. 향후 개·할머니·연인 동행의 별도 실루엣과 보스별 전용 음향은 제작 및 플레이 검증이 필요하다.

앱 종료·전화·방향 전환은 입력 상태를 정리하고 진행을 보존한다. 광고 종료나 결제 복귀를 자동 점프로 해석하면 안 된다. 프레임이 느릴 때 여러 번의 점프나 충돌을 한꺼번에 처리하지 않는다. 장식은 움직임 줄이기 설정을 존중한다.

## 5. 자연스러운 수익 모델

가격은 판매 가격이 아닌 테스트 가설이다. 국가별 실제 가격과 세금은 스토어 상품 정보로 표시해야 한다.

| 상품 | 내용 | 가격 가설 | 제안 시점 |
|---|---|---:|---|
| 달의 옷장 | 기본 보상과 다른 실루엣의 스킨·잔상 묶음 | 3,900원 | 3회 완주와 3분 플레이 이후, 성공 화면의 보조 링크 |
| 창작자 응원 | 전용 의상·명찰 등 명확히 보이는 꾸미기 | 6,900원 | 3일 이상 재방문한 이용자가 직접 선택 |
| 다음 꿈 | 완성된 새 세계·새 보스·새 음악 | 6,900원 | 기존 여정 완료 후, 실제 콘텐츠가 준비됐을 때 |
| 광고 체험 | 특정 의상 잠깐 체험 | 무료 | 옷장에서 직접 요청, 최대 하루 3회 |

기본 게임에는 강제 전면 광고와 스태미나 결제, 패배 직후 구매 팝업, 무작위 유료 뽑기, 순위 우위를 파는 부활을 도입하지 않는다. 초기 리텐션을 확보하기 전에 상품 수를 늘리지 않는다. 선택형 제안은 하루 1회 이하이고, 닫은 사용자에게 반복하지 않는다. 아동 모드에서는 개인화 과금 제안과 광고를 비활성화한다.

`release-policy.js`는 이 노출 조건만 구현한다. UI의 신뢰 가능한 권한 화면을 위한 보조 함수이며, 로컬 함수나 저장소가 유료 자산의 보안 경계가 될 수 없다. 실제 결제와 광고 플래그는 꺼져 있다. 판매할 실제 스킨 묶음·확장팩도 아직 제작되지 않았다.

## 6. 실제 결제·광고 연결 설계

서버 테이블은 account, purchase, entitlement, reward_transaction, entitlement_event를 분리한다. purchaseToken은 중복 처리 방지 키로 사용하고, 계정과 package/product를 대조한다. 구매 상태가 PURCHASED이고 서버 검증이 성공한 경우에만 권한을 부여한다. PENDING에서는 대기 상태를 표시한다. 검증·권한 기록·acknowledge 작업을 재시도 가능한 작업으로 처리한다. 환불·취소 이벤트는 권한을 회수하고 감사 기록을 남긴다. 복구 버튼은 현재 스토어 계정의 구매를 서버에서 다시 확인해야 한다.

광고 보상은 명시적 선택 → 광고 준비 → 표시 → 서버 서명 검증 → 중복 transaction 차단 → 보상 기록 순서다. 광고를 닫은 콜백만으로 보상을 지급하지 않는다. 실패·오프라인에는 대가 없는 기본 플레이를 유지한다. 보상 확정이 늦으면 대기 상태를 표시하고 동일 거래를 다시 지급하지 않는다.

필요한 실제 연결: Play Console 상품/테스트 사용자, 개발자 API 계정 권한, 검증 서버와 DB, RTDN, AdMob 앱/광고 단위, 개인정보 동의 흐름, 실기기 테스트, 서명된 AAB. 계정이나 식별자를 임의로 만들어 연결 완료라고 표시할 수 없다. 현재 단일 HTML은 connect-src none이므로 상용 서버를 붙이는 네이티브 브리지/네트워크 정책과 버전도 별도 검토한다.

## 7. 수익성 시나리오

아래는 전망이나 업계 평균이 아닌 계산 예시다. 광고는 DAU×1인당 일 노출×eCPM÷1000×30, 구매는 MAU×월 구매 전환×평균 결제액×가정 정산률로 계산했다. 정산률 85%는 분석 가정이며 실제 플랫폼 수수료·세금·환불·국가 차이는 따로 적용해야 한다.

| 시나리오 | DAU / MAU | 구매 전환 / 객단가 | 일 광고 / eCPM | 월 구매 정산 가정 | 월 광고 가정 | 합계 |
|---|---:|---:|---:|---:|---:|---:|
| 작은 검증 | 1,000 / 10,000 | 0.5% / 4,900원 | 0.2 / 3,000원 | 208,250원 | 18,000원 | 226,250원 |
| 성장 검증 | 10,000 / 100,000 | 1% / 5,900원 | 0.4 / 6,000원 | 5,015,000원 | 720,000원 | 5,735,000원 |
| 큰 성장 | 50,000 / 500,000 | 2% / 7,900원 | 0.6 / 9,000원 | 67,150,000원 | 8,100,000원 | 75,250,000원 |

서버·개발·아트·음악·CS·세금·광고비는 위 합계에서 빠지지 않았다. 이 숫자를 순이익으로 해석하면 안 된다. 성장 검증에서도 유료 유입비가 월 수익을 초과할 수 있다. 실제 90일 코호트 LTV가 CPI보다 높고 회수 기간이 감당 가능할 때만 유료 마케팅을 확대한다. 1위 달성은 코드나 디자인만으로 보장할 수 없다.

## 8. 출시 순서와 판단 기준

1. 내부 검증: 100개 슬롯별 증거표와 정상 입력 완주, 저장 복구, 오류 보고, 저사양 기기 프레임을 확보한다.
2. 소규모 외부 플레이: 첫날 50~100명의 실제 이용자 관찰. 설명을 추가하기 전에 헷갈리는 장면과 실패 이유를 수정한다.
3. 제한 출시: 최소 2주 코호트로 튜토리얼 완료·D1/D7·세션·충돌·프레임·이탈 원인을 본다. 광고는 초기에 꺼 둔다.
4. 수익 실험: 자발적 옷장 상품 1개부터 시작한다. 구매 흐름 전체, 환불·복구·중복·오프라인을 검증한다.
5. 확장: 구매 전환만이 아니라 잔존·평점·CS·환불과 장기 수익을 함께 판단한다.

내부 목표 가설: 튜토리얼 완료 85% 이상, D1 35% 이상, D7 12% 이상, crash-free session 99.8% 이상. 업계 상위권 기준을 인용한 값이 아니며 충분한 표본과 신뢰구간으로 재설정해야 한다. 60fps 목표는 저사양 실기기에서 p95 프레임 시간과 발열까지 측정한다.

출시 첫날에는 크래시·구매·저장 장애를 우선 감시하고 신규 상품 노출을 원격으로 끌 수 있어야 한다. 첫 주에는 난이도·이탈 지점을 조정하되 구매한 가치를 훼손하지 않는다. 둘째 주 이후에 새 스킨·짧은 도전을 추가하고 확장팩은 완성 콘텐츠가 있을 때 판매한다.

## 9. 남은 완료 조건

R80은 검토 가능한 실행본과 소스다. 원작 전체 동등성, 100개 정상 완주, Android 실기기 장기 품질, 모든 동행/보스의 새 아트, 청음 검수, 상용 결제·광고, 프로덕션 서명 및 스토어 제출은 남아 있다. 이를 끝내지 않은 상태에서 '모든 개발 완료' 또는 '1위 수준 검증 완료'라고 쓰지 않는다.
