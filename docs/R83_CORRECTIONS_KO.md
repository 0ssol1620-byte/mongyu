# R83 시작 화면·동작·원작 표현 수정

사용자가 R82 Android에서 보고한 초기 타이틀 노출, 뒤로 꺾인 무릎, 벽 회전 끊김, 낮은 속도감과 원작과 다른 캐릭터/사각형 표현을 수정했다. R82 위에 업데이트할 수 있도록 applicationId와 테스트 서명 키를 유지하고 versionCode를 83으로 올렸다. 실기기 검증이나 원작 전체 동등성 검증은 아니다.

## 원인과 변경

- 시작 화면: HTML의 본문은 처음부터 표시되지만 게임 코드와 큰 내장 자산은 뒤에서 로드되고 있었다. body의 최종 상태와 표시 컨트롤러가 초기화되기 전에는 이전 타이틀/버튼 CSS가 적용돼 잠깐 노출됐다. 이제 처음에는 단색 바탕과 몽유 로고만 표시한다. 앱과 장면/컨트롤러가 준비된 뒤 화면을 공개한다. JavaScript를 비활성화해 초기화 전 상태를 재현했을 때 R82의 기존 메뉴 노출과 R83의 차단을 확인했다.
- 무릎: Canvas의 아래 방향이 양수인 좌표계에서 관절 굽힘 부호를 반대로 선택했다. 이전 길이 검사만으로 이 문제를 잡지 못했다. 이제 앞으로 굽는 방향을 검사하며, 발의 주기를 실제 표시 이동 거리에 연결해 접지 중 발이 미끄러지지 않도록 했다.
- 벽 회전: R82는 face가 바뀌면 보간을 끄고 위치/방향을 한 번에 바꿨다. 또한 카메라의 선행 시선도 동시에 바뀌었다. 이제 두 접선의 교점을 찾아 지면 경로를 따라 이동하고 몸의 각도를 최단 방향으로 연결한다. 공중에서는 지면 경로와 안쪽 높이를 함께 보간한다. 긴 순간이동·충격·재시작은 즉시 표시한다. 판정 좌표는 수정하지 않는다. 카메라는 같은 표시 각도를 사용하고 따라오는 지연을 줄였다.
- 속도감: 일반 플레이의 초기 native speed 설정을 default(95ms)에서 fast(75ms)로 변경했다. 같은 네이티브 갱신 횟수가 약 26.7% 빠르게 진행된다. 명시적인 느린 설정과 속도 변경 미션은 기존 선택을 유지한다. 카메라의 기준 폭도 420에서 360으로 조정했다. 원작 실기기와 동일한 속도라고 주장하지 않는다.
- 캐릭터: 후드·얼굴 마스크·스카프를 제거하고 기본 모습을 작은 머리와 가느다란 검은 실루엣으로 바꿨다. 노인/동행 역할과 기존 의상 ID/저장은 유지한다. 밝은 의상에는 가는 윤곽을 넣어 밝은 배경에서도 구분한다. 옷장 미리보기도 실제 실루엣에 맞췄다.
- 사각형: 화면에 고정된 네온 상자 배경과 점선 같은 테두리 레일을 제거했다. 네이티브 지형의 실제 16단위 열과 높이/방향에 맞춘 평면 셀을 표시한다. 마스크 스테이지는 실제 점유 셀을 유지하고, 투사체도 실제 크기의 평면 셀로 그린다. 이전에는 지형 높이가 바뀌는 열 사이를 선으로 연결해 경사면처럼 보이게 하던 부분도 셀 단위로 바뀌었다. 밝은 색면과 장면별 팔레트를 적용했다.

## 원작과의 관계

참고한 원작 자료는 R82 검토에 링크한 신봉구의 2007년 제작자 글과 플레이 스크린샷이다. 이번 기본 캐릭터와 타일은 원작에 가까운 방향으로 다시 그린 자체 표현이며 원본 스프라이트/팔레트 파일을 추출한 것이 아니다. 따라서 원작과 픽셀 단위 동일하거나 모든 네모 패턴의 외형을 완전히 복원했다고 말할 수 없다. 음악도 R82의 자체 제작 12곡을 유지한다.

## 확인한 범위

- 웹 전체 검사 120개: 119 통과, 실패 0, 배포하지 않는 외부 감사 어댑터 1개 생략.
- 무릎 굽힘 방향, 접지 중 발 고정, 네 방향의 모서리 위치/각도 연속성, 공중 회전, 순간이동/충격 제외, native 셀 위치, 초기 표시 차단 및 빠른 기본 속도/느린 설정 보존을 검사했다.
- 같은 입력으로 74개 물리 스테이지를 원래 tick과 각각 12단계 비교하는 상태·난수·이벤트·결과 검사는 유지하고 통과했다. 원래 엔진 여섯 파일의 해시도 유지한다. 앱의 기본 속도를 fast로 선택하는 것은 명시적인 제품 설정 변경이다.
- 실제 native stage 3의 두 회전(update 88, 129)을 분할해 표시 좌표를 점검했다. 한 회전을 8개 간격으로 나눴을 때 최대 위치 변화는 각각 약 4.25, 4 world units였다. 이는 테스트 샘플이며 실기기 프레임 측정이 아니다.
- 브라우저에서 부팅·옷장 저장 복구·이야기·플레이·일시정지/재개·네 가지 화면 크기·오프라인 부팅을 확인했다.
- Android 콜백 VM 검사 5개를 통과했고 APK를 SDK 36/JDK 21로 컴파일했다. 서명 v2/v3, 정렬, ZIP 무결성 및 내장 HTML의 최종 R83 바이트 동일성을 검사했다. R82와 같은 인증서인지도 대조했다. 실제 Android 기기에 설치·플레이하지는 않았다.

새 측정과 빌드 증거는 evidence/r83-signed-apk.json 및 evidence/r83-corrections.json에 있다. 이전 R31 전용 테스트와 과거 릴리스 문서는 해당 버전의 기록이다.

후속 렌더링 정리에서 각 셀의 Canvas 상태 저장/좌표 변환을 면 단위로 묶고 화면 밖 셀을 그리지 않도록 했다. 이 변경 뒤 집중 검사 30개 중 29개 통과·실패 0·외부 어댑터 1개 생략을 확인하고 브라우저/콜백/서명 검사를 다시 수행했다. CPU 4배 감속 스트레스 검사에서 draw 중앙값은 약 0.9ms지만 프레임 간격 p95는 약 81.5ms였다. 빠른 네이티브 틱의 순간 비용이 남아 있으므로 저사양 실기기 60fps나 모든 렉 해소를 주장하지 않는다.
